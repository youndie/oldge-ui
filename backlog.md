## Goal

Ship the oldge-ui design system — mid-2000s gloss, a toxic lime accent, three skins — as a Compose
Multiplatform component library whose every component **provably** matches the design system it was
built from: one reference PNG per component per skin, rendered from the design system's own
previews, and `viddikDesignParity` measuring the Compose render against it.

The design system is the brief, and it is frozen in [`reference/design-system/`](reference/design-system/)
at the version named in research §1.1. It is evidence, not a document this repository maintains.

## Order of work, and why it is this order

1. **What can invalidate the architecture comes first** (stage 0). Four questions — which fonts can
   be bundled, whether the grain noise can be reproduced, whether the reference pipeline measures
   anything but font differences, and where parity's floor sits — each change how every component
   is built or verified. None is estimated around.
2. **The token layer and the materials** (stage 1): tokens generated from `tokens.json`, the theme
   with its three skins, the fonts, the gloss/bevel/grain primitives, the press feedback, the icon
   set, and the screenshot suite that guards all of it. Every component reads these; a component
   built before them is rebuilt after them.
3. **Components, grouped as the design system groups them** (stage 2). Each item ports the
   design system's preview demo as a fixture, per skin, and closes on a parity number.
4. **Screens that stress the system** (stage 3): the six stress screens and three showcase screens
   of the design system, rebuilt from the components — the check that the components compose.
5. **The library as a product** (stage 4): the sample app, the catalogue, accessibility, motion
   polish.

## Decisions not to re-litigate

The reasoning for each lives in [research](docs/research/research-architecture.md) §2; this is the
list an item can be checked against in one glance.

- **`Oldge` in every identifier** (D1); the design system's `og-` CSS classes and `OldgeUI`
  namespace are not API names.
- **No Material artefact in the core** (D2). The design system follows Material's *inventory*, not
  its implementation.
- **References are rendered from the design system's previews by this repository's own script**
  (D3), with reduced motion and bundled fonts, at the preview's content size.
- **Tokens are generated from `reference/design-system/tokens.json`** (D4), never typed.
- **1 CSS px = 1 dp; 1 rem = 16 sp** (D5).
- **Texture is on in parity** (B-04): the Kotlin `feTurbulence` port matches Chrome's tiles, so the
  reference renderer and the `OldgeDemo` harness both draw the grain; neither sets texture off.
- **Loop merges its own branches, locally** — see [CLAUDE.md](CLAUDE.md).
- **An item is blocked by every item whose component its previews show** (found on B-20):
  a fixture is the preview string for string, so a Badge inside a ListItem's preview is B-31's
  work first, and so is the Badge that Tabs renders for a tab's count (found on B-25). `scripts/preview_deps.py --check` holds `blocked_by` to the previews and rejects
  cycles, in `make gate`.
