# B-42 — The component catalogue: a previews registry and a generated docs/components.md

Past fifty components, "which composable is in which file and what shows it" is a question an
agent asks every session. kvadrant-ui answers it with a generated catalogue that `check` holds
against the sources.

- **The decision and its reason.** A registry `id → @Composable` of one bare instance per
  component, a generator writing `docs/components.md` (component, file, design-system group,
  reference stems, the design-system README), and a check that fails when the file is stale or
  names a component that no longer exists. Link it from `CLAUDE.md`'s "How to start a session".
- Rejected: a hand-written table — the kind of list that is wrong within a sprint.

- AC: the catalogue lists all 51 components; editing one row by hand fails the check.
- Anchors: `docs/components.md`, `scripts/component_catalog.py`,
  `kvadrant-ui/scripts/component_catalog.py`.

## Findings (2026-09-25)

- **`docs/components.md`**, generated by `scripts/component_catalog.py`, has three tables:
  - **all 51 exports of `index.d.ts`**, each with its composables, its file, its design-system
    group (from the preview's `@dsCard`), its reference stems, its golden groups, its README, and
    the first sentence of its KDoc;
  - **what the library offers beyond the exports**, four composables: `OldgeActions`,
    `OldgeScreenBody`, `OldgeText` and `OldgeTheme`;
  - **the nine pages** and their screens in `sample`.

  It is linked from `CLAUDE.md`'s "How to start a session" as step 3.
- **The registry of bare instances is the one that exists: viddik's.** The item asked for a
  registry `id → @Composable` of one instance per component. kvadrant-ui built a previews module
  for that. Here every component already has parity fixtures in viddik's `GeneratedViddikRegistry`,
  grouped by the design system's component name, and `ScreenshotSuiteTest` holds that set to the
  design system's previews both ways. A second registry would be a second list to keep in step.
  So the catalogue's golden column reads the fixtures through their goldens, which the suite test
  holds one to one.
- **The one hand-kept part is a map of eight names**, each checked against the sources:
  - `INSTEAD`: Chip is `OldgeAssistChip`, `OldgeFilterChip` and `OldgeInputChip`; ListSection is
    `oldgeListSections` and `OldgeListSectionHeader`;
  - `ALSO`: `OldgeIconButton`, `OldgeExtendedFab`, `OldgeFabDock`, `OldgeLazyPullRefresh`.

  Every other export is `Oldge<Name>`.
- **The check, in `make check`:**
  - the file is stale or edited by hand;
  - an export has no composable;
  - a map entry names what does not exist;
  - a page has no screen.

  Every public composable is in one of the tables by construction, and a unit test asserts it.
- **Verified:**
  - `scripts/test_component_catalog.py` (in the gate) checks a hand-edited row, a map entry that
    outlived a rename, and every public composable listed.
  - By hand: `OldgeBadge` renamed in its row made `make check` exit 2, naming the catalogue.
- **ChipGroup's group** is «— (no preview)»: it is exported without a preview, the one
  `ScreenshotSuiteTest` already knows.
